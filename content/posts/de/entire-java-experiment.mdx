## Was Entire wirklich speichert

Entires Pitch beginnt, in Lizzies Worten, bei einem echten Problem. **Agenten erzeugen inzwischen mehr Code, als ein Mensch Zeile für Zeile prüfen kann**, und ein Pull Request zeigt nur den Diff. Nie *warum* ein Agent drei Ansätze ausprobierte, bevor der vierte funktionierte.

<Quote author="Lizzie Siegle" role="Developer Advocate, Entire">
Ein Pull Request zeigt dir nur den Diff. Das Warum zeigt er nie.
</Quote>

Entires Antwort: die ganze Session, Prompts, Überlegungen, jeden Tool-Aufruf, jede Sackgasse, an den Commit hängen, als **Checkpoint** – ein versteckter Git-Ref, der bei jedem Commit oder Push ins eigene Repository geschrieben wird. *Man kann sich das wie einen Flugschreiber vorstellen, der am eigenen Code festgeschraubt ist.* Anders als eine echte Blackbox liegt dieser Flugschreiber allerdings in einem Flugzeug, das einem **bereits gehört**: im eigenen Git-Repository, nicht auf einem Server von Entire.

## Ein Prompt baute in elf Minuten ein spielbares Kartenspiel

Der Bau selbst hatte mit Entire nichts zu tun, das sei klar gesagt. Ein Satz in Claude Code, *erstelle ein Fantasy-Kartenspiel in Java FX*, kein Lastenheft, keine Rückfragen, keine Skills im Einsatz, [zu sehen bei 13:48](https://www.youtube.com/live/Z-8V8xg4K-k?t=828s). **Elf Minuten später** stand ein funktionierendes Maven-Projekt mit bestandenen Tests, und Claude Code machte von sich aus mit der Java-FX-Oberfläche weiter, [zu sehen bei 26:12](https://www.youtube.com/live/Z-8V8xg4K-k?t=1572s).

So eine Lockerheit funktioniert nur, wenn man auf den Fragenkatalog verzichtet, den manche KI-Workflows einfordern. Lizzie nutzt dafür sonst ein Skill-Paket namens [Superpowers](https://github.com/obra/superpowers), für testgetriebene Entwicklung und Code-Reviews; ich nutze sonst [BMad](/de/blog/bmad-method/) für die Projektplanung, [worüber wir bei 16:06 sprachen](https://www.youtube.com/live/Z-8V8xg4K-k?t=966s). **Keiner von uns wollte das hier.**

<Quote author="Lizzie Siegle" role="Developer Advocate, Entire">
Ich musste meiner CLAUDE.md-Datei sagen: Nutz Superpowers nicht für alles. Nur wenn ich es dir sage, denn ich hab es was Einfaches gefragt, und es hat zurückgefragt.
</Quote>

Das ist eine Vorliebe, kein Mangel bei einem der beiden Werkzeuge: Beide sollen einen Agenten *bremsen*, und für eine kurze Demo ist genau das nicht gefragt.

## Das Dashboard sieht alles, und genau das ist unangenehm

Nach dem Commit meldete Entires Analytics-Ansicht den Schaden: **rund 112.000 Tokens** für diesen einen Prompt, [zu sehen bei 39:20](https://www.youtube.com/live/Z-8V8xg4K-k?t=2360s). Claude Code meldet Verbrauch in Tokens, GitHub Copilot rechnet in AI Coins. Wenn Entire die Schicht ist, durch die beides läuft, ist das die erste gemeinsame Währung, mit der ich Agentenkosten über Tools hinweg vergleichen kann.

Dasselbe Dashboard schlüsselt den Token-Verbrauch pro Mitwirkendem auf, Input gegen Output. Lizzies Einschätzung: Hoher Input bei niedrigem Output bedeutet meist eingefügte Dokumentation; niedriger Input spricht für knappe Prompts. *Ein wirklich nützliches Signal*, wie ein Teammitglied tatsächlich mit einem Agenten arbeitet.

Es ist aber auch, ohne großen Zusatzaufwand, **ein Überwachungswerkzeug**. Das Dashboard zeigt nicht nur, dass jemand viele Tokens verbraucht hat, sondern auch, was diese Person dafür tatsächlich getippt hat, mit Zeitstempel und Namen. *Unangenehm* in dem Moment, in dem man sich vorstellt, wie eine Führungskraft genau so mitliest.

## Eine kleine Windows-Unannehmlichkeit

Die Entire-CLI unter Windows zu installieren geschah vor dem Stream, nicht während der Session: Das Installationsskript setzt Bash voraus, also brauchte ich zuerst [Scoop](https://scoop.sh/), laut [Entires eigener Installationsanleitung](https://docs.entire.io/cli/installation), [Feedback, das ich Lizzie bei 34:17 gab](https://www.youtube.com/live/Z-8V8xg4K-k?t=2057s). Nichts Dramatisches, nur eine kleine Hürde, bevor das Tool läuft. Live lief die Aktivierung im Repository dann reibungslos: `entire enable -y` hängte sich ohne Widerstand ein, [zu sehen bei 12:05](https://www.youtube.com/live/Z-8V8xg4K-k?t=725s).

## Worauf wir keine klare Antwort bekommen haben

Lizzie zeigte zwei Features, die noch nicht öffentlich sind: **Trails und Gates**, [zu sehen bei 55:48](https://www.youtube.com/live/Z-8V8xg4K-k?t=3348s). Ein Trail bündelt ein Issue und einen Pull Request in einem Objekt, das ein Agent oder Teammitglied von der Kommandozeile aus durch Phasen bewegen kann.

Ein Gate ist eine Merge-Prüfung, die eine menschliche Freigabe verlangen kann, basierend auf einem Confidence-Score, den *Entires eigenes Modell* berechnet. Eine schlüssige Idee, klar noch nicht fertig.

Die Frage, auf die ich eigentlich eine Antwort wollte, blieb offen: Bleibt das Speichern hunderter Sessions pro Repository *schnell*, sobald ein Projekt echte Historie hat? Lizzie öffnete Entires eigenes CLI-Repository für Analysen pro Mitwirkendem, aber das ist ein junges, kleines Repository, nicht die jahrealte Codebasis, nach der ich eigentlich gefragt hatte.

Wir haben außerdem Entires drei [separat installierbare Skills](https://docs.entire.io/learn/skills) nie ausprobiert: [Search](https://github.com/entireio/skills/tree/main/skills/search) durchsucht vergangene Sessions nach Thema oder Datei, [Explain](https://github.com/entireio/skills/tree/main/skills/explain) sucht die Session hinter einer bestimmten Funktion oder Zeile, und [Handoff](https://github.com/entireio/skills/tree/main/skills/session-handoff) lässt einen anderen Agenten den Stand einer Aufgabe übernehmen, statt dass man ihn von Hand rekonstruiert. Vermutlich die bessere Version dessen, was das Dashboard tut: gespeicherte Historie, die ein Entwickler **abfragen** kann, statt die eine Führungskraft beobachtet.

## Abschließender Gedanke

Der Teil, der mich am Ende wirklich überzeugt hat, **hat mit dem Dashboard nichts zu tun**. Alles, was Entire speichert, liegt in einem Git-Branch im eigenen Repository. Hört man morgen auf, Entire zu nutzen, verschwinden weder Code noch Checkpoint-Historie in der Datenbank eines anderen. *Sie liegen weiter in dem Repository, das man ohnehin schon hatte.*

<Quote author="Lizzie Siegle" role="Developer Advocate, Entire">
Entwicklerinnen und Entwickler wollen sich nicht binden lassen. Wir mögen Wahlfreiheit, egal ob bei einem anderen Agenten oder einem anderen Harness. Wir leben in einer Welt mit vielen Modellen nebeneinander.
</Quote>

Das ist das eigentliche Argument dafür, Entire auszuprobieren: **Das Risiko, sich zu irren, ist nahezu null**, weil das Verlassen der Plattform nichts kostet, was man nicht schon besaß. Der Preis: Derselbe Rekorder, der die Überlegungen eines Teammitglieds festhält, bewahrt sie auch für jeden anderen mit Repository-Zugriff. Gut zu wissen, *bevor* man das für ein Team bewertet, nicht danach.
